# Grapple range and interaction review

Measured original radial limit: 400 px. Prototype default: 440 px (+10%), configurable `player.grapple_range`, with enforced 80–480 px bounds. Range tests exercise 399,400,420,440,441,480 px against the 440 default. 420 is accepted, 441 and 480 rejected; the original 400 setting remains available for rollback comparisons. This is an initial balance candidate, not creator-approved final tuning.

Facing tolerance (-100 behind), minimum rope (80), upward requirement (-35), airborne input condition and instantaneous press handling are unchanged. Selection remains nearest eligible target with stable list-order ties. Replaced the world-level 401 cutoff with the shared configurable range; null now denotes no target instead of incorrectly reserving world (0,0). Existing vectors remain supported.

Verified code defect: the old 520-pixel indicator used feet-distance, so it could advertise an unusable anchor. Indicator now uses exactly `can_tether_anchor`, including range, facing, airborne condition and clearance. It represents availability, not a pending input buffer; grounded players see inactive anchors. Q remains press-to-attach/hold-to-swing; no automatic repeated acquisition or input-buffer redesign.

Initial attachment now checks a ray from the hand origin to the anchor against solid layer 1, excluding the player. This prevents through-solid acquisition; `grapple_clearance_check=false` is an isolated rollback/tuning option. The rope does not wrap, and the integrator does not re-raycast every swing tick. Existing body collision releases the rope. Review awkward placements with LD-01; do not change the integrator to compensate for obstructed level design.

`scripts/grapple_anchor.gd` is an optional Node2D component. It exports enabled, attachment_offset and required_ability; supplies `get_attachment_position()` and `is_available_for(player)`; joins `kaze_grapple_anchor`. World collects only descendants of itself, leaving old Vector2 placements intact. Unknown requirements fail closed. Positions must use the current untransformed world/geometry coordinate space, matching the legacy anchors. No new placed objects or artwork were added. LD-01 owns representation, scene ownership, placement, occlusion and clearance.

Clearance assumptions: full swing arc must accommodate the 60-pixel capsule (14-pixel radius), not just the origin ray. Do not mount the exact attachment point inside a layer-1 solid; use an exposed attachment_offset. At 440 pixels, a longer pendulum changes its period naturally; the swing equations and pump remain identical. Tests preserve in-range initialization, slack/taut constraint, both pump directions and exact release velocity. Manual playtests must compare 400/420/440 on both facings, rising/falling, close to platforms and at full speed; obstruction changes may expose existing poor placements.
