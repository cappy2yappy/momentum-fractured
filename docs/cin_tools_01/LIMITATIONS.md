# Known limitations / placeholder inventory

- Prototype, draft review only. The playable integration is the R14↔R17 staircase in a separate demo process. Other ordinary routes and their automatic semantics stay inherited. Biome and boss templates are editable presentation compositions, not new gameplay events.
- TR-08 is an unmerged draft dependency (PR #64). The PR is stacked on its exact inspected head; Wave 3 / PR #74 is not imported. Integrators must preserve that dependency or explicitly rebase after its accepted merge.
- ART-08 is candidate animation, not creator-approved final animation. The intro reuses `stair_arrive_idle_settle` and holds its final pose; it does not claim to be a new gait. TR-08 performs the real staircase action with existing candidate enter/loop/exit/settle clips and existing root-motion staging.
- Background `district-fidelity.png` and foreground `terrain-materials.png` are temporary environment staging from existing assets, not finished biome-specific illustration. Template titles and boss subject are explicit authoring placeholders. Replace artwork on native nodes/keys; timing is independent.
- Boss subject is temporarily Kaze; no boss or story canon is invented. Destination labels in generic templates need author input. Approved character image files, physics, pivots and original TR-08 implementation remain unchanged.
- Music and sound event references are silent placeholders. No unapproved audio, plugin or generation is added. Assign native stream resources to audition the event and volume tracks.
- Root motion metadata is retained in native Animation metadata. Intro tracks do not apply it to the live collision body. TR-08 owns stage root motion and tread registration. New clips must supply correct cell/pivot/hframes/frame durations; the tool does not invent registration or animations.
- Reduced motion has its own short fade timeline. Spatial motion must stay absent when authoring it. F6 mid-intro switches to that alternative; TR-08 retains its existing shortened, fixed-camera mode.
- Native editor saves are the authoring persistence mechanism. The runtime preview is read-only and does not save arbitrary in-memory scrubs or overwrite scene resources. There is no custom drag-and-drop clip browser or plugin.
- Death/respawn and unrelated room rebuilds supersede the request; resuming a stale trip after death would violate checkpoint authority. Skip, pause/focus loss and watchdog complete an accepted trip once, subject to the existing gate check. A paused loader resumes only when the existing pause UI resumes the game.
- Input authoring hotkeys are desktop keyboard controls. Creator approval of feel/art and a Windows editor/controller pass remain outstanding; macOS rendered automation is evidence of behavior, not creator visual acceptance.
