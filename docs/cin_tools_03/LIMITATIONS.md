# Fidelity and prototype limits

The approved flat art defines Kaze's appearance. The original and active approved sheets remain byte-identical. PR #30 remains an identity reference; its four held keys and flattened paint layers do not supply complete cycles or independently painted hidden surfaces.

The rig reuses the existing **candidate** ART-08 profile cutouts from PR #62, not newly approved body-part artwork. Nine source files, including part metadata, are copied byte-for-byte from commit `98d639f32c34d862bbe6ecf1fb4a8c70e1736414`; `assets/cin_tools_03/rig_parts/PROVENANCE.json` records exact hashes. Native sprite regions reuse the candidate limb tubes, with rigid FK joints rather than the offline renderer's deformation. No reference was uploaded to a generation service, and no generation, new purchase or external asset-processing service was used.

Visible limitations include rectangular/overlapping cut edges, elbow/knee seams, rigid fabric, stretched tube proportions, limited profile identity and duplicate far/near parts. Rotation cannot reveal the missing back of a limb, recover hidden clothing, or turn a flat face naturally. Hair/ribbon follow-through is a few keyed rotations. No mesh weights, IK, constraint solver or automatic anatomy reconstruction exists here.

The default hybrid study runs existing approved sheet frames and switches abruptly at 1.5 s to the cutout braking candidate. That switch changes drawing style/proportions; it is deliberately labelled. The braking root decelerates and stops by 2.55 s; the final root remains stationary. That numerical property does **not** establish planted feet. Foot sliding, shoe height, ground contact, weight transfer and silhouette must be judged visually and improved with authored keys/parts. Rig-only inspection during the sprint holds a sparse pose rather than inventing a completed rig run cycle. Sprite-only inspection holds the last source frame after the run segment; it is not finished sprite braking.

PR #85's three selected Image4 sprint keys and unrelated guard keys are sparse timing studies. PR #95 explicitly leaves production staircase drawing slots empty. This tool neither fills those slots nor claims to complete ART-10, directional staircase gait or Canal Doorway turns. Better production fidelity needs separated artist-reviewed parts, occluded surface paint and/or matching contact, passing, braking and settle drawings. A tool alone cannot supply those pixels under the current no-generation/no-transfer constraint.

Creator acceptance is pending. This is an isolated presentation prototype: no campaign trigger, StoryDirector integration, playable physics change, save migration or canon addition. The Director has two fixed seed shots and basic canvas framing; full sequencing, frame/mode key authoring, timing changes, audio and event tracks remain native Godot Animation-panel work. No dedicated shot reorder, sprite exposure-sheet UI, arbitrary rig import wizard or movie-export product is claimed. The recording helper packages review evidence only. Windows, gamepad usability and export certification remain untested.
